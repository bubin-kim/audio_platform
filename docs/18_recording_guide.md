# 18. 녹음 가이드 (수집 현장용)

> 상태: **v1.0 (2026-08-06)** — 파일럿 2개(260804_004·005) 실측 기반.
> 대상: 차량 경적음 수집. 다른 도메인은 §5의 방법으로 목표치를 다시 측정한다.
> 왜 필요한가: 전처리·자동검출은 **이미 묻힌 소리를 살리는 사후 수단**이라 한계가
> 뚜렷하다(docs/17 §7). 애초에 잘 녹음하는 것이 데이터 품질을 결정한다.

## 1. 파일럿 실측 — 무엇이 문제였나

| 지표 | 260804_004 | 260804_005 | 목표 |
|---|---|---|---|
| 피크 레벨 | -12.4 dBFS | **-19.9 dBFS** | **-12 ~ -6 dBFS** |
| 배경 바닥 (전대역 p10) | -54.2 | -52.2 | 낮을수록 좋음 |
| 전대역 여유 (p90-바닥) | 21.7 dB | **14.9 dB** | **20 dB 이상** |
| **경적대역 배경 (300–1500Hz p30)** | **-63.8** | -76.5 | **-70 dB 이하** |
| **경적대역 검출 여유** | **8.8 dB** | 22.4 dB | **15 dB 이상** |
| 같은 설정 검출 결과 | **0개** | 16개 | — |

**핵심 발견**: 두 파일의 경적 최대 에너지는 거의 같다(-54.9 vs -54.0dB).
차이는 **배경 소음**이다 — 004는 배경이 12.7dB 더 높아 경적이 묻혔고,
같은 검출 설정에서 **0개**가 잡혔다. 즉 문제는 "경적이 작다"가 아니라
**"배경이 크다"**이다.

## 2. 다음 수집 때 지킬 것 (우선순위 순)

### ① 배경 소음이 작은 시간·장소를 고른다 — 가장 효과 큼
- 차량 통행·환기구·공조기 소리가 적은 시간대 (심야·이른 아침)
- 마이크를 벽·기둥에서 떨어뜨려 반사음 줄이기
- **바람이 있으면 윈드스크린 필수** (저주파 배경을 크게 올린다)

### ② 마이크를 소리원에 가깝게
- 거리가 절반이 되면 신호는 +6dB, 배경은 그대로 → **여유 +6dB**
- 004처럼 배경이 큰 환경일수록 거리 효과가 결정적

### ③ 게인을 올려 피크 -12 ~ -6 dBFS를 맞춘다
- 005는 -19.9dBFS로 **너무 작게** 녹음됐다 (양자화 여유 낭비)
- 단, 클리핑(0dBFS 도달)은 절대 금지 — 되돌릴 수 없다
- 녹음기 미터가 가장 큰 경적에서 -6dBFS 근처를 치도록 맞춘다

### ④ 방향성 마이크를 쓴다 (있다면)
- 무지향 대신 카디오이드 → 뒤쪽 환경음을 6~10dB 억제

## 3. 현장 체크 (첫 파일 1개로 3분 안에)

수집 시작 전 **시험 녹음 1개**를 반드시 진단한다:

```bash
# 프로젝트 루트에서
cd backend && uv run python ../.claude/skills/audio-diagnose/diagnose.py <파일> \
    --threshold-db -40 --min-silence-sec 0.3
```

또는 플랫폼에 업로드 → **원본 파일 섹션 → "배경 제거 (묻힌 소리 찾기)"** 로
스펙트로그램을 본다. 경적이 밝은 점으로 보이면 OK, 안 보이면 §2를 다시 조정한다.

**합격 기준**: 경적대역 검출 여유 **15dB 이상** (아래 §5 방법으로 측정).
005(22.4dB)는 합격, 004(8.8dB)는 불합격 — 004 방식으로 계속 수집하면
**자동 검출이 동작하지 않는다**.

## 5. 목표치를 다른 도메인에 다시 잡는 법

경적이 아닌 도메인(심음·산업음 등)은 대역이 다르므로 이 문서의 숫자를 그대로
쓰면 안 된다. `audio-diagnose` 스킬로 **대역별 여유 표**를 뽑아
가장 여유가 큰 대역을 고르고, 그 대역에서 15dB 이상을 목표로 삼는다.
(대역별 여유 표 출력은 docs/17 E-M2에서 스킬에 추가 예정.)

## 6. 이미 수집한 파일은?

- **005 계열(여유 20dB 이상)**: 자동 검출 커팅이 정상 동작 → 그대로 사용

## §5. 마이크: Zoom H3-VR (앰비소닉) — 채널 해석 주의

**녹음 기기는 Zoom H3-VR이고, 4채널은 B-format(W/X/Y/Z)이다.**
(사용자 확인 2026-09-07, 신호 특성으로 교차 검증)

| 채널 | 의미 |
|---|---|
| ch0 = W | 전방향(무지향) |
| ch1 = X | 앞 ↔ 뒤 (8자 지향) |
| ch2 = Y | 좌 ↔ 우 (8자 지향) |
| ch3 = Z | 위 ↔ 아래 (8자 지향) |

### 일반 마이크 어레이 기준으로 판단하면 오진한다

216개 전수 실측:

| 지표 | 실측값 | 일반 어레이 기준 | 앰비소닉 기준 |
|---|---|---|---|
| 채널 간 상관 | 중앙 +0.074 | 0.3~0.9여야 정상 | **0 근처가 정상** |
| 채널별 피크 시각 차 | 중앙 0.272초 | 최대 ~3ms | **개념 자체가 무의미** |
| ch0 / 나머지 평균 | 1.97배 | — | **정상**(W=전방향 합) |

**X·Y·Z는 수학적으로 직교**하므로 상관 0이 설계상 당연하다. 또 B-format은
이미 캡슐 신호를 합성한 결과이고 캡슐 간격도 ~2cm(0.06ms)라 **"채널 간
도착 시간차"라는 개념이 성립하지 않는다.** 측정된 0.272초는 물리적 지연이
아니라 서로 다른 지향 패턴이 배경음에 다르게 반응한 결과다.

> **실사고**: 이 사실을 모른 채 신호만 보고 "채널 정합성이 깨졌다 —
> 4채널이 하나의 어레이로 동작하지 않는다"고 보고했다. **마이크 모델을
> 먼저 확인했으면 5분에 끝났을 일이다.** 신호 해석 전에 장비 사양을 확인할 것.

### 채널 활용 (순음성 기준, 216개)

| 방식 | 순음성 중앙 | 14dB 이상 |
|---|---|---|
| ch0(W) 단독 | 15.2dB | 113/216 (52%) |
| **현재 mean** | 17.6dB | 119/216 (55%) |
| 파일별 최선 채널 | 17.7dB | **129/216 (60%)** |

최선 채널은 파일마다 고르게 갈린다(ch0 23% / ch1 24% / ch2 29% / ch3 25%)
— 소리가 온 방향에 따라 유리한 지향 성분이 다르기 때문이며 앰비소닉에서
자연스럽다.

**미시도 — 빔포밍**: B-format은 후처리로 임의 방향의 지향성 마이크를
만들 수 있다(`out = W + X·cosθcosφ + Y·sinθcosφ + Z·sinφ`). 라벨에
각도(angle 0~7)·거리가 이미 있으므로 차량 방향으로 빔을 만들면 그 방향
소리만 키우고 배경음을 줄일 수 있다. -63dBFS로 묻힌 신호에 유효할
가능성이 있으나 **아직 시도하지 않았다.**

### 원본 WAV 헤더에서 확인된 녹음 설정 (2026-09-10)

`bext`·`iXML` 청크 실측(1일차·4일차 동일):

| 항목 | 값 |
|---|---|
| 기기 | ZOOM H3-VR Handy Recorder |
| **Rec Mode** | **AmbiX** ← 앰비소닉 확정 |
| **Mic Position** | **Upright** |
| **Correction Filter** | **Off** |
| 포맷 | `A=PCM, F=48000, W=24, M=multi` |
| **채널 순서** | **zTRK1=W · zTRK2=Y · zTRK3=Z · zTRK4=X** |

> **주의: 채널 순서가 W·Y·Z·X다** (일반적인 AmbiX 표기 W·X·Y·Z가 아니다).
> 헤더를 확인하지 않고 W·X·Y·Z로 가정해 채널별 분석을 했던 적이 있다 —
> 전 채널 평균(`channel="mean"`)을 쓰는 검출 경로는 순서와 무관해 영향이
> 없지만, **채널별 분석·빔포밍은 이 순서를 반드시 반영해야 한다.**

**게인 = 10 / 100** (사용자가 기기 본체에서 확인, 2026-09-11).

게인 값은 **파일에 기록되지 않는다** — H3-VR은 트랙 이름만 남기고 입력
레벨을 쓰지 않는다(bext·iXML 어디에도 없음). 기기 본체 REC LEVEL 화면에서만
확인 가능하다. **다음 수집부터는 녹음 노트에 반드시 적을 것.**

게인 10은 100단계 중 하위 10%로 **매우 낮은 설정**이며, 비프음이
-63dBFS(일반 권장 -20~-6dBFS보다 43~57dB 낮음)로 기록된 직접적 원인이다.

**왜 10이었나: H3-VR의 공장 초기값을 그대로 사용했다** (사용자 확인
2026-09-11 — "게인 조정한다는 개념 자체를 몰랐다", 본체 측면에 게인 조절
레버가 있다는 것을 수집 완료 후에 발견). 의도적 선택이 아니라 **설정
항목의 존재를 몰랐던 것**이다.

> **수집 전 점검에서 빠졌던 항목이다.** 녹음 기기의 입력 게인은 수집
> 품질을 좌우하는 1순위 설정인데, 사전 점검 목록에 없어 초기값으로
> 4일치 216개를 전부 수집했다. 아래 §6 체크리스트는 이 사고에서 나왔다.

### 실측 녹음 레벨 (게인 대신 논문에 쓸 수 있는 값)

| 일차 | RMS | 피크 | 비프대역 SNR | 검출 매칭률 |
|---|---|---|---|---|
| 1일차 | -53.7dB | -37.4dB | 16.0dB | 80% |
| 2일차 | -68.4dB | -49.5dB | 24.4dB | 100% |
| 3일차 | **-76.9dB** | -56.4dB | **44.4dB** | **100%** |
| 4일차 | -61.9dB | -45.5dB | **12.7dB** | **60%** |

전 일차가 일반 권장 범위(피크 -20~-6dBFS)보다 **25~44dB 낮다.**

### ★ 핵심: 검출을 좌우하는 것은 게인이 아니라 **대역 SNR**이다

**녹음 레벨과 검출 성능은 무관하다** — 3일차는 RMS가 가장 낮은데(-76.9dB)
비프대역 SNR이 44.4dB로 가장 높아 100%이고, 1일차는 레벨이 가장 높은데
(-53.7dB) SNR 16dB로 80%다.

비프음 대역(1900~2100Hz)의 **배경 소음 절대량**:

| 일차 | 대역 배경 | 3일차 대비 |
|---|---|---|
| 3일차 | 2.45e-14 | 1배 |
| 2일차 | 1.09e-12 | 44배 |
| 4일차 | 3.14e-12 | **128배** |
| 1일차 | 2.31e-11 | **943배** |

게인을 올려도 배경이 함께 커지므로 **SNR은 그대로다.**

### 게인 10에 대한 정확한 평가 (둘 다 사실이다)

| 관점 | 판단 |
|---|---|
| **양자화 여유** | ❌ **문제다.** 게인 10/100은 24bit의 하위 비트만 쓰는 셈이라 약한 신호의 분해능이 낮아지고, 사람이 귀로 검수하는 것도 불가능하다(증폭 사본 필요) |
| **검출 성능(SNR)** | ✅ **원인이 아니다.** 게인은 신호와 배경을 함께 키우므로 대역 SNR을 바꾸지 못한다 — 3일차가 가장 낮은 레벨로 녹음됐는데 검출 100%인 것이 증거 |

**다음 수집 권고 (우선순위 순)**

1. **타겟 대역이 조용한 시간대·위치 선택** ← SNR을 실제로 개선하는 유일한 방법
2. **게인 상향** (10 → 40~60 권장) — SNR은 안 바뀌지만 양자화 여유가 늘고
   **사람 청취 검수가 가능해진다.** 단, 클리핑 여부를 현장에서 확인할 것
3. 녹음 노트에 **게인·마이크 위치·0° 기준 방향**을 반드시 기록

### 미확인 사항 (사용자 확인 필요)

- **기기 REC LEVEL 설정값**과 그렇게 설정한 이유 (파일에서 알 수 없음)
- 마이크 배치·방향 기준(0°가 어디인지)

## §6. 수집 전 기기 점검 체크리스트 (필수)

게인 설정 항목의 존재를 모른 채 초기값(10/100)으로 216개를 수집한 사고
(2026-08~09) 재발 방지. **녹음 나가기 전 기기에서 직접 확인하고, 값을
녹음 노트에 적는다.** 파일 헤더에 남지 않는 항목이 많다.

### 반드시 확인·기록할 것

| 항목 | 확인 위치 | 파일에 남나 | 이번 값 |
|---|---|---|---|
| **입력 게인(REC LEVEL)** | 본체 레버/메뉴 | ❌ **안 남음** | **10/100** |
| Rec Mode | 메뉴 | ✅ 남음 | AmbiX |
| Mic Position | 메뉴 | ✅ 남음 | Upright |
| Correction Filter | 메뉴 | ✅ 남음 | Off |
| 샘플레이트/비트depth | 메뉴 | ✅ 남음 | 48kHz/24bit |
| **마이크 0° 기준 방향** | 물리 배치 | ❌ **안 남음** | 미기록 |
| **마이크 높이·거리** | 물리 배치 | ❌ **안 남음** | 미기록 |
| Low Cut 필터 | 메뉴 | ❌ | 미확인 |
| Limiter/AGC | 메뉴 | ❌ | 미확인 |

### 현장 1분 테스트 (본녹음 전)

1. 타겟 소리를 실제 거리에서 한 번 울리고 **레벨 미터 확인**
   - 피크가 **-20 ~ -6 dBFS** 구간에 오도록 게인 조정
   - 빨간 불(클리핑)이 뜨면 게인을 낮춘다
2. 조용한 상태로 5초 녹음 → **배경 소음 레벨** 확인
3. 녹음 노트에 게인 값과 미터 판독값을 적는다

### 이번 수집에서 얻은 교훈

- **게인은 SNR을 바꾸지 못한다**(신호·배경을 함께 키움) — 그래도 올려야
  하는 이유는 **양자화 여유와 사람 청취 검수 가능성** 때문이다.
- 게인 10에서는 비프음이 -63dBFS라 **귀로 들을 수 없어** 사람 검수가
  원천 봉쇄됐다. 이것이 검증을 신호 지표에만 의존하게 만든 근본 원인이다.
