# 17. 이벤트 자동 검출 커팅 (V2-9)

> 상태: **설계안 (v1.0, 2026-08-05)** — 사용자 결정 반영: 검출 방식=대역 에너지,
> 조각 길이=고정 길이(이벤트 중심 ± 여유).
> 배경: 260804_005.WAV 실측 — 경적이 환경음에 묻혀 전대역 음량(silence_based)으로는
> 검출 불가(threshold 3dB 차이에 조각 수 1→69 널뜀). 반면 300~1500Hz 대역만 보면
> 16개 이벤트가 바닥 대비 +8~22dB로 뚜렷. 이 관찰을 커팅 전략으로 만든다.

## 1. 목표와 범위

- **새 커팅 전략 `event_detection`** — Project 설정으로 주파수 대역·검출 민감도·
  조각 길이를 받아, 이벤트를 자동으로 찾아 **고정 길이**로 자른다.
- 환경음에 묻힌 소리도 검출한다 (기존 silence_based가 못 하는 것).
- **도메인 독립(P1)**: 대역·임계값은 전부 `cutting_params`. 코드에 경적·심음 같은
  도메인 상수를 넣지 않는다.

**비목표**: 머신러닝 기반 분류(무슨 소리인지 판별), 다중 이벤트 종류 동시 검출,
실시간 스트리밍 검출.

## 2. 알고리즘 (실측 근거 포함)

```
1. 대역 통과 필터 (band_low_hz ~ band_high_hz)   ← scipy.signal.butter, 이미 있는 의존성
2. 100ms 창 RMS → dB 타임라인
3. 배경 수준 = p30 (하위 30% — 이벤트가 드물다는 가정)
4. 임계 = 배경 + threshold_above_bg_db
5. 임계 초과가 min_event_sec 이상 이어지면 이벤트 1개
6. 이벤트 중심 ± (segment_sec/2) → 고정 길이 조각
7. 조각끼리 겹치면 병합(merge_overlap=true) 또는 각각 유지
```

**260804_005.WAV 실측 (이 설계의 근거)**:

| 대역 | 바닥(p30) | 최대 | 여유 |
|---|---|---|---|
| 300~800Hz | -77.7 | -56.7 | 21.0dB |
| **300~1500Hz** | **-79.0** | **-56.5** | **22.5dB** |
| 1500~3000Hz | -81.6 | -59.5 | 22.1dB |

바닥+8dB 기준으로 16개 이벤트 검출(0.3~0.7초, +8.5~22.4dB). 사용자 청취 확인
결과 9.8초·161초 부근 = **경적 맞음**(179초는 아님 → 오탐 1건 확인됨,
threshold를 올리면 걸러질 가능성).

## 3. cutting_params (전부 Project 설정 — P1)

| 파라미터 | 타입 | 기본 | 설명 |
|---|---|---|---|
| `band_low_hz` | float | 없음(전대역) | 검출 대역 하한. 미설정 시 필터 없이 전대역 |
| `band_high_hz` | float | 없음 | 검출 대역 상한 |
| `threshold_above_bg_db` | float | 8.0 | 배경 대비 몇 dB 이상이면 이벤트로 볼지 |
| `min_event_sec` | float | 0.2 | 이 시간 이상 지속돼야 이벤트 (순간 잡음 제외) |
| `segment_sec` | float | **필수** | 잘라낼 고정 길이 (예: 5.0) |
| `pre_pad_sec` | float | segment_sec/2 | 이벤트 시작 기준 앞쪽 여유 |
| `merge_overlap_sec` | float | 0.0 | 이벤트 간격이 이보다 좁으면 하나로 병합 |

경적 예시: `{band_low_hz: 300, band_high_hz: 1500, threshold_above_bg_db: 8,
min_event_sec: 0.2, segment_sec: 5.0, pre_pad_sec: 2.0}` → "이벤트 시작 2초 전부터
5초"를 잘라낸다(요청하신 "앞뒤로 2초씩" 형태).

## 4. 아키텍처 (기존 커팅 전략과 동일 — 파일 1개 + registry 한 줄)

```
backend/app/audio/cutting/event_detection.py   ← CutStrategy 구현, 순수 로직(P2)
backend/app/audio/cutting/__init__.py          ← import 한 줄(registry 등록)
frontend/components/projects/CuttingConfigFields.tsx  ← CUTTING_MODES에 항목+입력 필드
```

- 기존 `fixed_interval`·`silence_based`와 완전히 같은 인터페이스
  (`validate_params` + `cut` → `Iterator[SegmentAudio]`) — 워커·서비스·API 변경 0.
- scipy는 이미 의존성에 있다(진단 스크립트에서 사용 중) — **새 라이브러리 없음**.
  ※ 확인 필요: `pyproject.toml`의 정식 의존성인지, 전이 의존성(librosa 경유)인지.
  전이 의존성이면 명시적으로 추가한다.

## 5. 검증 계획 (골든 케이스는 사람이 검수 — 전역 규칙 4)

1. **합성 신호 단위 테스트**: 배경 소음 + 알려진 위치의 톤 버스트 N개를 생성해,
   검출 개수·시작 위치가 기대와 일치하는지 (audio/ 독립 테스트).
2. **실파일 검증**: 260804_005.WAV에 경적 설정 적용 → 검출 결과를 **초 단위 목록으로
   사용자에게 제시**하고, 앞서 확인된 2개(9.8s·161s)가 포함되는지 + 오탐이 몇 개인지
   함께 보고. 사용자 승인 후에 이 결과를 골든 케이스로 삼는다.
3. **품질 검사 연동**: `expected_segments_per_source`와 함께 쓰면 "기대 30개인데
   12개 검출" 같은 경고가 자동으로 뜬다(docs/14) — 재녹음 판단 근거.

## 7. 리스크 / 한계

| 항목 | 내용 |
|---|---|
| 오탐/미탐 | 배경 대비 임계값 하나로는 완벽할 수 없다. 179초 사례처럼 경적 아닌 것도 잡힌다 — **커팅 후 스펙트로그램·재생으로 사람이 확인하는 것을 전제**로 한다 |
| 배경 추정 | p30을 배경으로 가정 — 이벤트가 전체의 30%를 넘게 차지하는 녹음에서는 배경이 과대추정돼 미탐이 는다 |
| 대역 선택 | 사용자가 대역을 모르면 쓸 수 없다 → audio-diagnose 스킬에 "대역별 여유 표" 출력을 추가해 고르도록 돕는다(E-M2에서 함께) |
| 고정 길이 | 이벤트가 segment_sec보다 길면 잘린다. 긴 이벤트가 흔한 도메인은 가변 길이 옵션을 후속 검토 |
