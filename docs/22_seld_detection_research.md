# 22. SED 기반 딥러닝 탐지 연구 설계 (2026-08-27)

> V2-9(event_detection, docs/17)가 규칙 기반 탐지의 한계를 드러낸 뒤,
> "플랫폼 개발 → 연구 방향" 전환점에서 사용자가 제시한 7가지 고민을
> 하나의 연구 파이프라인으로 정리한 문서. **아직 미구현 — 설계만.**
> 구현 전 사용자 승인 필요(CLAUDE.md §4).

---

## 1. 배경 — 7가지 고민을 어떻게 하나로 엮었나

사용자가 제시한 7가지:
1. 스펙트로그램엔 안 보이는데 귀로는 들리는 케이스 (원인: 주파수 대역이 배경과 겹침)
2. 눈에도 안 보이고 소리도 안 들리는 케이스
3. 탐지+추적 알고리즘 개발 방향
4. fixed_interval 10초 고정 커팅 데이터 활용
5. 논문 구조(알고리즘 개발 → 데이터셋 구축 → 서비스 배포)에서 지금 데이터로 갈 길
6. 노이즈 유무에 따른 모델 성능 비교 (배경음 있을 때/없을 때 모델 A가 잘 되는지)
7. 분리해놓은 샘플 청취 분류

**대화로 확정된 관계**: 7번(청취)은 파이프라인의 시작이 아니라 **끝**이다 —
"6번까지 하고, 알고리즘으로 분리한 음원을 듣고 분류"하는 최종 QA 단계.
즉 순서는 **4(학습 데이터 준비) → 6(모델 학습·노이즈 비교) → 1·2(한계
분석) → 3(추적, 향후 과제) → 7(결과물 청취 검증)**.

이 문서는 4·6번(지금 바로 시작 가능한 부분)의 설계를 담는다. 1·2번은
6번 실험 결과에서 자연히 드러나는 한계 유형으로 다룬다. 3·7번은 이후
마일스톤으로 미룬다.

## 2. 핵심 제약 — SELD 계열을 그대로 못 쓰는 이유

Conformer-SELD·SELDnet·EIN-SELD·EASE-SELD는 전부 **DOA(방위) 추정**을
출력에 포함한다. 이건 마이크 배치가 규칙적으로 캘리브레이션돼 있어야
학습 가능한데, **우리 마이크 4개는 배치가 불규칙하고 위치가 기록되어
있지 않다**(사용자 확인, 2026-08-27). 따라서:

- **DOA 헤드는 뺀다.** GCC-PHAT 기반 TDOA/방위 추정은 마이크 거리
  파라미터가 필수라 지금 데이터로 실행 자체가 불가능하다.
- **SED(이벤트 존재 탐지)만 가져온다.** 4개 모델의 "다채널 입력
  인코더 + CRNN/Conformer 시퀀스 모델링" 아이디어만 참고해 우리
  데이터 규모(2,160개 학습 조각)에 맞게 간소화한 구조를 새로 설계한다.
- DOA는 **향후 과제**로 명시한다 — 마이크를 정사각형 등 고정 배치로
  재배치하고 거리를 기록한 뒤 재녹음해야 재개 가능.

## 3. GT(정답) — 재생 로그 기반 침산적 라벨

**핵심 발견(2026-08-27, 사용자 확인)**: 화재경보음은 사람이 나중에
들어서 GT를 만드는 게 아니라, **녹음 시점에 이미 정확한 재생 시각을
알고 있다** — 1~4일차 216개 원본 전부 동일하게 **5, 15, 25, 35, 45,
55, 65, 75, 85, 95초**에 정확히 10회 재생. 배경음악은 "몇 초에
울렸다"는 로그가 없는 연속 배경(노이즈 조건으로만 취급, §5).

이건 §17(event_detection)에서 썼던 "위상 근사 GT"(경험적 추정)와
다르다 — **재생 로그 자체가 정답**이므로 침산적으로 100% 신뢰할 수
있어 보이지만, 실제 재생 장비 오동작·녹음 시작 지연 가능성이 있어
**그대로 전체 채택 전에 소량 청취로 검증**한다(§4).

### fixed_interval과의 정렬 확인 (코드 레벨 검증 완료)

`app/audio/cutting/fixed_interval.py`는 항상 `start_frame=0`부터
`interval_sec`(10초) 단위로 자르므로, 매 조각의 상대 위치 **5초
지점**에 이벤트가 오는 게 보장된다:

```
조각 [0-10]초 → 이벤트 5초 (상대위치 5초, 조각 중앙)
조각 [10-20]초 → 이벤트 15초 (상대위치 5초, 조각 중앙)
... (총 10개/원본, 90-100초까지)
```

NAS 실측(2026-08-26)으로 fixed_interval 4개 dataset(5~8) 전부
**정확히 540개(54원본×10)**, duration 전부 10.0초 균일 확인 —
`drop_last_shorter_than_sec`로 자투리가 제거돼 경계가 깨끗하다.

## 4. GT 신뢰도 검증 계획 (구현 전 첫 마일스톤)

**목적**: "5초 지점에 이벤트가 있다"는 침산적 라벨을 2,160개 전체에
적용하기 전에, 실제로 재생 장비가 설계대로 동작했는지 확인한다.

**절차**:
1. 1~4일차 각각에서 소량 샘플(예: 일차당 3~5개 원본)을 무작위로 골라
   사람이 직접 청취
2. 5,15,...,95초 근방에 실제로 소리가 울렸는지, 위치가 어긋나지
   않았는지 확인
3. 전부 일치하면 → 216개 전체(2,160개 조각)에 침산적 라벨 적용
4. 어긋나는 사례가 있으면 → 빈도·패턴(특정 일차에 집중되는지 등) 파악
   후 재생 로그를 신뢰할 수 있는 범위만 골라 쓰거나, docs/17의 위상
   근사 GT와 교차검증

**주의**: 1·4일차(아울렛)는 배경음악 때문에 이 검증이 2·3일차보다
어려울 수 있다(§17 §2l의 배경 dB 차이 실측 참고) — 하지만 재생
로그는 배경음악과 무관하게 "재생 명령이 나간 시각"이므로, 소리가 안
들려도(§1의 케이스 2) 라벨 자체는 유효할 수 있다는 점을 검증 중
염두에 둘 것.

## 5. 노이즈 조건 (6번 실험의 조건 변수)

이미 실측으로 확정된 구분 — 재녹음 없이 바로 쓸 수 있다:

| 조건 | 일차 | 절대 dB 평균 (docs/17 §2l 실측) |
|---|---|---|
| 배경음악 있음(아울렛) | 1일차, 4일차 | -58.8, -66.4 |
| 배경음악 없음(조용함) | 2일차, 3일차 | -73.3, -73.8 |

6번 실험(모델 A를 노이즈 유무에 따라 각각 학습/평가)은 이 4개
dataset을 그대로 조건군으로 쓴다.

## 6. 모델 설계 (SED 전용, 간소화 CRNN)

### 6.1 입력

- 4채널 원본에서 각 채널의 log-mel spectrogram (4채널)
- IPD(채널 간 위상차, 최대 6채널 쌍) 포함 여부는 **실험으로 검증**
  한다 — 마이크 배치가 불규칙하면 IPD가 오히려 노이즈가 될 수 있어,
  "IPD 포함 vs 미포함"을 GT 검증 완료 후 비교 실험으로 확정한다
  (CLAUDE.md 원칙: 그럴듯해 보이는 특징도 실측 없이 채택하지 않는다).

### 6.2 구조 (초안, 데이터 규모 2,160개에 맞춘 간소화)

```
입력 (Batch, C, Time, Mel) — C=4(스펙트로그램만) 또는 4+6(IPD 포함)
  → Conv2D 블록 ×3 (BatchNorm + ReLU + MaxPool, 주파수 축만 축소)
  → Bi-GRU (시퀀스 모델링)
  → FC + Sigmoid → 이진 확률 (경보음 있음/없음)
```

- num_classes = 1 (경보음 단일 클래스, 다중 클래스 SELD 원안에서 축소)
- 출력 단위: fixed_interval 조각(10초) 단위 이진분류로 시작
  (사용자 결정, §3) — 프레임 단위 시퀀스 태깅은 향후 확장 여지로 남김

### 6.3 평가

- `app/audio/evaluation.py`의 `evaluate()` 패턴을 그대로 재사용할 수
  있는지 검토 — 조각 단위 이진분류라면 accuracy/precision/recall로
  충분하고, 프레임 단위로 확장하면 기존 TP/FP/FN 매칭 로직이 유용하다.
- **노이즈 유무 비교**: 같은 모델을 (2·3일차만 학습→평가) vs (1·4일차
  포함 학습→평가) 두 조건으로 나눠 성능 차이를 수치로 비교한다.
- 규칙 기반(event_detection, nperseg=4096)의 위상GT 성능(F1 61~96%,
  docs/17 §2l)을 baseline으로 나란히 보고한다.

## 7. 1·2번 고민과의 연결 (한계 분석 — 6번 실험 이후)

- **1번(대역 겹침, 안 보이지만 들림)**: 모델이 이 케이스를 규칙 기반보다
  잘 잡는지가 6번 실험의 핵심 관전 포인트. 실패하면 IPD·다채널 정보가
  실제로 도움이 안 된다는 반증이 되고, 성공하면 논문의 핵심 기여가 된다.
- **2번(눈에도 안 보이고 안 들림)**: 데이터 자체의 정보 이론적 하한.
  모델이 여기서 계속 실패하면, 이건 알고리즘 한계가 아니라 **녹음
  환경/장비의 한계**로 정직하게 보고한다(§8 참고).

## 8. 논문 구조 제안 (5번)

"알고리즘 개발 → 데이터셋 구축 → 서비스 배포" 표준 순서에 지금
데이터를 대입하면:

1. **데이터셋 구축**: 216개 원본, 4일치, 노이즈 조건 2종(아울렛/조용),
   정확한 재생 로그 기반 GT — 이미 상당 부분 확보됨. 첫 기여로 제시
   가능.
2. **알고리즘 개발**: 규칙 기반(event_detection) 한계 규명(§17 전체
   기록) → SED 전용 경량 모델로 개선. "왜 규칙 기반이 실패하는지"를
   정량 분석(대역 겹침·배경음 dB 실측)한 뒤 "그래서 이런 모델을
   설계했다"는 논리가 자연스럽다.
3. **서비스 배포**: 플랫폼은 이미 존재(NAS 자체 호스팅) — 마지막
   단계는 준비돼 있다.

**제안 논문 기여 포인트**:
- 정확한 재생 로그 기반 GT를 가진 실환경(아파트/아울렛) 화재경보음
  데이터셋
- 규칙 기반 탐지의 정량적 실패 모드 분석(대역 겹침, 배경음 dB 영향)
- 마이크 배치 캘리브레이션 없이도 다채널 정보를 활용하는 경량 SED
  모델 (DOA 없는 저비용 환경에 특화)

## 9. 마일스톤 (제안)

- **M1**: GT 신뢰도 검증(§4) — 소량 청취로 재생 로그 정확도 확인
- **M2**: 침산적 GT 전체 적용 + 학습/평가 데이터 분할(노이즈 조건별)
- **M3**: SED 모델 최초 버전 구현 + 학습 파이프라인
- **M4**: 노이즈 유무 비교 실험(§6.3) + baseline(규칙 기반) 대조
- **M5**: 1·2번 한계 분석 정리 + 논문 구조(§8) 초안
- **(보류)** DOA — 마이크 배치 고정 재녹음 이후
- **(보류)** 3번 추적 알고리즘 — SED 성능 확인 이후
- **(보류)** 7번 최종 청취 분류 — M4 결과물 기준
